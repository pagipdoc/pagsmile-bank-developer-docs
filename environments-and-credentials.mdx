Pagsmile Open API authenticates requests with an access key (AK) and a secret key (SK). Sign the exact body bytes you send, and verify callback signatures before processing events.

## Environments

Append the endpoint path to the base URL for your environment. Use the matching credential pair.

| Environment | Base URL |
| --- | --- |
| Sandbox | `https://ebanking-openapi-sandbox.pagsmile.com.br` |
| Production | `https://ebanking-openapi.pagsmile.com.br` |

Use Sandbox while integrating. Credential entry, signature tools, and online testing in these docs are Sandbox only. The Production address is shown for reference. When you move to Production, configure the base URL and credentials together on your server; do not enter Production AK/SK in these docs.

## Credentials and account selection

Send your AK in `X-Client-ID`. Keep the SK on your server and use it to calculate signatures; do not send it in requests.

Use an active credential. For ACCOUNT and USER credentials, the owning user's OpenAPI access must also be enabled.

<Tabs>
  <Tab title="ACCOUNT" icon="building-columns">
    The credential is bound to one account. For account operations, omit both `X-ISPB` and `X-Account-Number` to use that account.

    If you send account headers, send both with nonempty values matching the bound account. You cannot select another account with this credential.
  </Tab>
  <Tab title="USER" icon="user">
    For account operations, send both `X-ISPB` and `X-Account-Number` for an account you are authorized to access. Include both in the signature.

    For USER-scoped managed-account and event-subscription operations, omit both account headers. Those operations use the credential's owner instead of a selected account.
  </Tab>
  <Tab title="PLATFORM" icon="server">
    Use this credential only where the endpoint allows PLATFORM access. Follow that endpoint's header requirements.

    <Warning>PLATFORM credentials cannot call account-scoped payment, balance or Pix-key endpoints. Use an ACCOUNT or USER credential for those operations.</Warning>
  </Tab>
</Tabs>

Preserve leading zeros in account identifiers. <Tooltip tip="Identificador do Sistema de Pagamentos Brasileiro: the institution identifier used to select a bank account.">ISPB</Tooltip> identifies the institution; `X-Account-Number` identifies the account.

Sending only one account header, an empty pair, or an unauthorized target fails account selection. The result has `code` equal to `4004003` (`Permission denied`).

See [account models](/account-models) for the relationship between users and accounts. Check each endpoint's credential requirements before you call it.

## IP allowlist

Configure the outbound IP address your server uses to reach the API. The allowlist accepts comma-separated exact IP addresses and CIDR ranges.

Use [Set up API access](/api-access-setup) to find your public IP address, update the **Allow List** in the dashboard, and check each entry. The API compares exact IPv6 entries as text, and the dashboard field removes letters; if your IPv6 address contains `a` to `f`, call the API over IPv4 and allow the IPv4 address.

An empty allowlist denies all requests. A source IP that matches no entry returns `4004103`. The current message is the unrendered template `IP address has no permission: {{.ip}}`; it does not show your IP.

The API playground on each API page sends requests directly from your browser, so the API checks this computer's public IP. Your servers reach the API from their own addresses. To test from the docs, also allow this computer's address. See [Use the signature tool](#use-the-signature-tool).

## Sign requests

All v3 endpoints use `POST` with a JSON body. Set `Content-Type` to `application/json` and use the path and fields documented for the endpoint.

| Header | What to send |
| --- | --- |
| `Content-Type` | `application/json`. Included in the signature. |
| `X-Client-ID` | Your AK. Required. |
| `X-Timestamp` | Current Unix time in milliseconds, as a decimal integer string. Required. |
| `X-Nonce` | A fresh random identifier for each attempt. Required. |
| `X-Content-Hash` | SHA-256 of the raw body, in lowercase hexadecimal. Optional for API requests. |
| `X-Signature` | HMAC-SHA256 signature, as 64 lowercase hexadecimal characters. Required. |

The API allows a timestamp difference of five minutes. It records each AK and nonce pair for ten minutes before checking the signature.

Generate a new nonce and timestamp for every attempt, including retries after authentication failures. A failed signature check still consumes the nonce.

A nonce protects an individual request against replay. It does not replace an endpoint's idempotency key; follow that endpoint's retry rules.

### Build the string to sign

<Steps>
  <Step title="Hash the body">
    Serialize the JSON once. Calculate SHA-256 over the exact bytes you will send and encode the digest in lowercase hexadecimal.

    Calculate this hash even when you omit `X-Content-Hash`. If you send that header, it must match the body hash.

    For `POST /v3/bank_account`, send the JSON object `{}`. Its hash differs from the hash of an empty body.
  </Step>
  <Step title="Prepare the path and query">
    Use the URL-decoded request path without the scheme, domain, query or fragment. Decode percent escapes once and preserve the resulting path.

    Do not normalize or re-encode it. For the documented ASCII endpoint paths, use the path unchanged.

    Sort query parameter names lexicographically. Preserve the original value order for repeated names.

    Encode names and values using Go `url.QueryEscape` rules, including spaces as `+`, then join the pairs with `&`.

    For example, `z=9&b=2&a=hello world` becomes `a=hello+world&b=2&z=9`. Use an empty query section when there are no parameters.

    If query parsing fails, the signature calculation uses the raw query string. Avoid malformed query strings.
  </Step>
  <Step title="Canonicalize the signed headers">
    Use lowercase header names. Trim leading and trailing whitespace from values, sort names lexicographically, and join `name:value` lines with LF (`\n`).

    Include `content-type`, `x-client-id`, `x-nonce` and `x-timestamp`. Include `x-content-hash` only when its value is nonempty.

    Include `x-ispb` and `x-account-number` whenever you send them. Explicitly empty account headers still enter the signature, but fail account selection.

    Exclude `x-signature`, `host`, `content-length`, `user-agent` and all other headers. Send timestamp and nonce strings without padding or surrounding whitespace.
  </Step>
  <Step title="Calculate the signature">
    Join the seven sections below with one LF (`\n`) separator. Keep the empty query section, and do not add a trailing LF.

    Calculate HMAC-SHA256 over the UTF-8 string using the raw SK as the key. Encode the signature in lowercase hexadecimal and send it in `X-Signature`.

    Send the same body and headers you signed. Do not format or reserialize the JSON after signing.
  </Step>
</Steps>

```text
UPPERCASE_METHOD
REQUEST_PATH
CANONICAL_QUERY
CANONICAL_HEADERS
CONTENT_HASH
TIMESTAMP
NONCE
```

`CANONICAL_HEADERS` can contain several lines. The content hash, timestamp and nonce also appear in the final three sections; keep this repetition.

### Signed request samples

Set `PAGSMILE_AK` and `PAGSMILE_SK` on your server. `PAGSMILE_BASE_URL` defaults to Sandbox.

These samples call `POST /v3/bank_account` with an ACCOUNT credential, the body `{}`, and no query or account headers.

For USER account selection, add and sign both account headers. The signature tool below handles that pair.

Set `PAGSMILE_TIMEOUT_SECONDS` to a positive integer; the samples default to 30 seconds. Python applies this timeout to blocking socket operations; the other samples use an overall request deadline.

Connection failures and timeouts write errors to standard error and exit unsuccessfully, separately from JSON business results. The samples do not retry automatically.

<CodeGroup>

```bash cURL
# Requires curl, OpenSSL and Python 3. Export PAGSMILE_SK; the HMAC helper reads it from the environment, never command-line arguments. Set PAGSMILE_AK and PAGSMILE_SK. PAGSMILE_BASE_URL defaults to the Sandbox.
BASE_URL="${PAGSMILE_BASE_URL:-https://ebanking-openapi-sandbox.pagsmile.com.br}"
REQ_PATH="/v3/bank_account"
TIMEOUT_SECONDS="${PAGSMILE_TIMEOUT_SECONDS:-30}"
case "$TIMEOUT_SECONDS" in
  ''|*[!0-9]*|0*) echo 'PAGSMILE_TIMEOUT_SECONDS must be a positive integer' >&2; exit 1 ;;
esac
BODY='{}'

# Sign the exact bytes you send. Use a new nonce and timestamp on every attempt.
TS=$(( $(date +%s) * 1000 ))
NONCE=$(openssl rand -hex 16)
HASH=$(printf '%s' "$BODY" | openssl dgst -sha256 -hex | sed 's/^.* //')
STRING_TO_SIGN=$(printf 'POST\n%s\n\ncontent-type:application/json\nx-client-id:%s\nx-content-hash:%s\nx-nonce:%s\nx-timestamp:%s\n%s\n%s\n%s' \
  "$REQ_PATH" "$PAGSMILE_AK" "$HASH" "$NONCE" "$TS" "$HASH" "$TS" "$NONCE")
SIGNATURE=$(printf '%s' "$STRING_TO_SIGN" | python3 -c 'import hashlib, hmac, os, sys; print(hmac.new(os.environ["PAGSMILE_SK"].encode("utf-8"), sys.stdin.buffer.read(), hashlib.sha256).hexdigest())')

curl -sS --connect-timeout "$TIMEOUT_SECONDS" --max-time "$TIMEOUT_SECONDS" -X POST "$BASE_URL$REQ_PATH" \
  -H "Content-Type: application/json" \
  -H "User-Agent: your-app/1.0" \
  -H "X-Client-ID: $PAGSMILE_AK" \
  -H "X-Timestamp: $TS" \
  -H "X-Nonce: $NONCE" \
  -H "X-Content-Hash: $HASH" \
  -H "X-Signature: $SIGNATURE" \
  --data-raw "$BODY"
```

```python Python
# Set PAGSMILE_AK and PAGSMILE_SK. PAGSMILE_BASE_URL defaults to the Sandbox.
import hashlib, hmac, json, os, secrets, sys, time, urllib.error, urllib.request

BASE_URL = os.environ.get("PAGSMILE_BASE_URL", "https://ebanking-openapi-sandbox.pagsmile.com.br")
PATH = "/v3/bank_account"
AK, SK = os.environ["PAGSMILE_AK"], os.environ["PAGSMILE_SK"]
TIMEOUT_SECONDS = int(os.environ.get("PAGSMILE_TIMEOUT_SECONDS", "30"))
if TIMEOUT_SECONDS <= 0:
    sys.exit("PAGSMILE_TIMEOUT_SECONDS must be a positive integer")

payload = {}
body = json.dumps(payload, separators=(",", ":"), ensure_ascii=False).encode("utf-8")

# Sign the exact bytes you send. Use a new nonce and timestamp on every attempt.
ts, nonce = str(int(time.time() * 1000)), secrets.token_hex(16)
content_hash = hashlib.sha256(body).hexdigest()
string_to_sign = "\n".join([
    "POST", PATH, "",
    "content-type:application/json",
    f"x-client-id:{AK}",
    f"x-content-hash:{content_hash}",
    f"x-nonce:{nonce}",
    f"x-timestamp:{ts}",
    content_hash, ts, nonce,
])
signature = hmac.new(SK.encode(), string_to_sign.encode(), hashlib.sha256).hexdigest()

req = urllib.request.Request(BASE_URL + PATH, data=body, method="POST", headers={
    "Content-Type": "application/json",
    "User-Agent": "your-app/1.0",
    "X-Client-ID": AK,
    "X-Timestamp": ts,
    "X-Nonce": nonce,
    "X-Content-Hash": content_hash,
    "X-Signature": signature,
})
try:
    with urllib.request.urlopen(req, timeout=TIMEOUT_SECONDS) as resp:
        print(resp.read().decode("utf-8"))
except urllib.error.HTTPError as err:
    print(err.read().decode("utf-8"))
except (urllib.error.URLError, TimeoutError, OSError) as err:
    print(f"Transport failure: {err}", file=sys.stderr)
    sys.exit(1)
```

```go Go
// Set PAGSMILE_AK and PAGSMILE_SK. PAGSMILE_BASE_URL defaults to the Sandbox.
package main

import (
	"bytes"
	"crypto/hmac"
	"crypto/rand"
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"io"
	"net/http"
	"os"
	"strconv"
	"strings"
	"time"
)

func main() {
	baseURL := os.Getenv("PAGSMILE_BASE_URL")
	if baseURL == "" {
		baseURL = "https://ebanking-openapi-sandbox.pagsmile.com.br"
	}
	path := "/v3/bank_account"
	ak, sk := os.Getenv("PAGSMILE_AK"), os.Getenv("PAGSMILE_SK")
	timeoutSeconds := 30
	if value := os.Getenv("PAGSMILE_TIMEOUT_SECONDS"); value != "" {
		var err error
		timeoutSeconds, err = strconv.Atoi(value)
		if err != nil || timeoutSeconds <= 0 {
			fmt.Fprintln(os.Stderr, "PAGSMILE_TIMEOUT_SECONDS must be a positive integer")
			os.Exit(1)
		}
	}
	client := &http.Client{Timeout: time.Duration(timeoutSeconds) * time.Second}

	body := []byte(`{}`)

	// Sign the exact bytes you send. Use a new nonce and timestamp on every attempt.
	ts := strconv.FormatInt(time.Now().UnixMilli(), 10)
	nb := make([]byte, 16)
	rand.Read(nb)
	nonce := hex.EncodeToString(nb)
	sum := sha256.Sum256(body)
	contentHash := hex.EncodeToString(sum[:])
	stringToSign := strings.Join([]string{
		"POST", path, "",
		"content-type:application/json",
		"x-client-id:" + ak,
		"x-content-hash:" + contentHash,
		"x-nonce:" + nonce,
		"x-timestamp:" + ts,
		contentHash, ts, nonce,
	}, "\n")
	mac := hmac.New(sha256.New, []byte(sk))
	mac.Write([]byte(stringToSign))
	signature := hex.EncodeToString(mac.Sum(nil))

	req, err := http.NewRequest("POST", baseURL+path, bytes.NewReader(body))
	if err != nil {
		fmt.Fprintln(os.Stderr, "Transport failure:", err)
		os.Exit(1)
	}
	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("User-Agent", "your-app/1.0")
	req.Header.Set("X-Client-ID", ak)
	req.Header.Set("X-Timestamp", ts)
	req.Header.Set("X-Nonce", nonce)
	req.Header.Set("X-Content-Hash", contentHash)
	req.Header.Set("X-Signature", signature)
	resp, err := client.Do(req)
	if err != nil {
		fmt.Fprintln(os.Stderr, "Transport failure:", err)
		os.Exit(1)
	}
	defer resp.Body.Close()
	out, err := io.ReadAll(resp.Body)
	if err != nil {
		fmt.Fprintln(os.Stderr, "Transport failure:", err)
		os.Exit(1)
	}
	fmt.Println(string(out))
}
```

```java Java
// Java 17+. Set PAGSMILE_AK and PAGSMILE_SK. PAGSMILE_BASE_URL defaults to the Sandbox.
import java.net.URI;
import java.net.http.*;
import java.nio.charset.StandardCharsets;
import java.security.*;
import java.time.Duration;
import java.util.HexFormat;
import java.util.concurrent.TimeUnit;
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;

public class PagsmileRequest {
    public static void main(String[] args) throws Exception {
        String baseUrl = System.getenv().getOrDefault("PAGSMILE_BASE_URL", "https://ebanking-openapi-sandbox.pagsmile.com.br");
        String path = "/v3/bank_account";
        String ak = System.getenv("PAGSMILE_AK"), sk = System.getenv("PAGSMILE_SK");
        int timeoutSeconds = Integer.parseInt(System.getenv().getOrDefault("PAGSMILE_TIMEOUT_SECONDS", "30"));
        if (timeoutSeconds <= 0) throw new IllegalArgumentException("PAGSMILE_TIMEOUT_SECONDS must be a positive integer");

        byte[] body = """
            {}""".getBytes(StandardCharsets.UTF_8);

        // Sign the exact bytes you send. Use a new nonce and timestamp on every attempt.
        String ts = Long.toString(System.currentTimeMillis());
        byte[] nb = new byte[16];
        new SecureRandom().nextBytes(nb);
        String nonce = HexFormat.of().formatHex(nb);
        String contentHash = HexFormat.of().formatHex(MessageDigest.getInstance("SHA-256").digest(body));
        String stringToSign = String.join("\n",
            "POST", path, "",
            "content-type:application/json",
            "x-client-id:" + ak,
            "x-content-hash:" + contentHash,
            "x-nonce:" + nonce,
            "x-timestamp:" + ts,
            contentHash, ts, nonce);
        Mac mac = Mac.getInstance("HmacSHA256");
        mac.init(new SecretKeySpec(sk.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
        String signature = HexFormat.of().formatHex(mac.doFinal(stringToSign.getBytes(StandardCharsets.UTF_8)));

        HttpRequest request = HttpRequest.newBuilder(URI.create(baseUrl + path))
            .timeout(Duration.ofSeconds(timeoutSeconds))
            .header("Content-Type", "application/json")
            .header("User-Agent", "your-app/1.0")
            .header("X-Client-ID", ak)
            .header("X-Timestamp", ts)
            .header("X-Nonce", nonce)
            .header("X-Content-Hash", contentHash)
            .header("X-Signature", signature)
            .POST(HttpRequest.BodyPublishers.ofByteArray(body))
            .build();
        HttpClient client = HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(timeoutSeconds)).build();
        var pending = client.sendAsync(request, HttpResponse.BodyHandlers.ofString());
        try {
            HttpResponse<String> response = pending.get(timeoutSeconds, TimeUnit.SECONDS);
            System.out.println(response.body());
        } catch (Exception err) {
            pending.cancel(true);
            System.err.println("Transport failure: " + err);
            System.exit(1);
        }
    }
}
```

```php PHP
$response = curl_exec($ch);
if ($response === false) {
    fwrite(STDERR, 'Transport failure: ' . curl_error($ch) . PHP_EOL);
    curl_close($ch);
    exit(1);
}
curl_close($ch);
echo $response, PHP_EOL;
```

</CodeGroup>

### Use the signature tool

The tool calculates signatures in your browser without transmitting or persisting your SK. It removes the whitespace outside strings from the JSON before signing, without changing any value, and outputs a cURL command in bash syntax with that exact body. If you entered your keys in [Set up API access](/api-access-setup), the tool fills them in from this tab's memory.

The method is fixed to `POST`. Enter an ASCII endpoint path without percent escapes, query or fragment. Unsupported paths are rejected before signing.

For other paths, sign on your server using the [path and query rules](#build-the-string-to-sign). Include both account headers when your credential requires them.

In the Sandbox, **Send to Sandbox** sends the signed request from your browser, so the API checks this computer's IP against the allowlist. The API's CORS policy doesn't allow `X-ISPB` or `X-Account-Number` from browsers; for requests with those headers, run the cURL command on your server.

## Authentication errors

All JSON business results, including authentication errors, return HTTP 200. Read `code` before `data`; HTTP 200 alone does not prove success.

| `code` | Example message | What to do |
| --- | --- | --- |
| `4004101` | `Authorization is required` | Send `X-Client-ID` with your AK. |
| `4004102` | `Invalid {{.header}} header` | Check `X-Timestamp`, `X-Nonce` and `X-Signature`. The message does not name the header. |
| `4004103` | `IP address has no permission: {{.ip}}` | Allow the server's outbound IP or CIDR. |
| `4004104` | `X-Content-Hash does not match request body` | Hash the exact bytes you send. |
| `4004105` | `X-Timestamp is invalid or expired` | Check your clock and generate a fresh timestamp. |
| `4004106` | `X-Nonce is invalid or has already been used` | Generate a new nonce for the attempt. |
| `4004107` | `X-Signature is invalid` | Check the SK and all seven signing sections. |
| `401` | `User is invalid` | Check credential status and the owner's OpenAPI access. |
| `4004003` | `Permission denied` | Check the credential type and target account. |

Only unreadable bodies or invalid JSON return HTTP 400 with a `text/plain` body. Include the response header `xxx-log-id` when you contact support.

Send a descriptive `User-Agent`, such as `your-app/1.0`. The network edge can block a missing value or a default library value such as `Python-urllib/3.12`. It returns HTTP 403 with the text `error code: 1010` before authentication runs. `User-Agent` is not signed, so changing it does not affect the signature.

For a signed JSON `POST` request, the API checks authentication in this order. It stops at the first failure.

<Steps>
  <Step title="Required headers">
    Check the required signature headers.
  </Step>
  <Step title="Timestamp">
    Validate the timestamp within the five-minute window.
  </Step>
  <Step title="Nonce">
    Record the AK and nonce pair for ten minutes. A failed signature check still consumes the nonce.
  </Step>
  <Step title="Signature and body hash">
    Verify the signature and body hash.
  </Step>
  <Step title="IP allowlist">
    Check the source IP against the allowlist.
  </Step>
  <Step title="Account target">
    Resolve the target account.
  </Step>
  <Step title="Owner's OpenAPI access">
    Check the owner's OpenAPI access for ACCOUNT and USER credentials.
  </Step>
</Steps>

The JSON business result returns with HTTP 200, including authentication failures. Read `code` to distinguish success from failure.

For the full catalog, see [authentication errors](/api-reference/error-catalog#authentication-errors).

## Verify callbacks

Callbacks use `POST`. Verify the signature with the SK associated with the received `X-Client-ID` before you process the event.

Keep the raw body bytes. Do not parse, format or reserialize the JSON before calculating its hash.

### Required callback headers

Callbacks carry all six headers below. Unlike API requests, callbacks require `X-Content-Hash`.

| Header | Verification rule |
| --- | --- |
| `Content-Type` | Use the received value, trimmed at the ends. Do not replace it. |
| `X-Client-ID` | Find the associated AK and SK. |
| `X-Timestamp` | Parse Unix milliseconds and check your agreed validity window. |
| `X-Nonce` | Check for 32 lowercase hexadecimal characters. |
| `X-Content-Hash` | Compare against SHA-256 of the raw body, in lowercase hexadecimal. |
| `X-Signature` | Compare against the expected HMAC-SHA256 signature using a constant-time comparison. |

Agree on a callback timestamp window for your integration and enforce it in your receiver. The API request window does not define your receiver's policy.

### Callback string to sign

Use the same seven-section layout, with the callback path in the second section. Join sections with LF and do not add a trailing LF.

```text
UPPERCASE_METHOD
CALLBACK_PATH
CANONICAL_QUERY
CANONICAL_HEADERS
CONTENT_HASH
TIMESTAMP
NONCE
```

Canonicalize the query as described in [Sign requests](#sign-requests). Preserve a trailing slash; use `/` when the callback URL has no path.

Include only `content-type`, `x-client-id`, `x-content-hash`, `x-nonce` and `x-timestamp` in the canonical headers.

Trim their values, sort lowercase names lexicographically, and join `name:value` lines with LF. Exclude `x-signature` and account-target headers.

Calculate HMAC-SHA256 with the associated SK. The expected result is 64 lowercase hexadecimal characters.

Keep the content hash, timestamp and nonce in both the header section and the final three sections.

### Callback path encoding

Use the path without the domain, query or fragment. The delivery type determines whether percent escapes remain in the signature path.

| Callback type | Signature path |
| --- | --- |
| ACCOUNT transaction callbacks | URL-decoded path |
| USER transaction callbacks | Path with URL escaping preserved |
| KYB and MED callbacks | Path with URL escaping preserved |

For `/hooks/%41`, the decoded path is `/hooks/A`; the escaped path remains `/hooks/%41`. Do not decode the escaped form before signing.

Use an ASCII callback path without percent escapes, such as `/pagsmile/webhooks`, so these forms are identical.

### Replay protection and acknowledgement

<Steps>
  <Step title="Validate the delivery">
    Check the required headers and timestamp. Calculate the body hash, build the string to sign, and compare signatures in constant time.

    Reject invalid deliveries before parsing their business data.
  </Step>
  <Step title="Prevent replay and save the event">
    After the signature passes, atomically check and record the AK and nonce pair. Couple replay protection with durable event storage.

    Deduplicate business processing using the identifiers defined for the callback type. A fresh nonce does not prove that the business event is new.
  </Step>
  <Step title="Acknowledge receipt">
    Return HTTP 200 after you have safely stored or queued the verified event. Process the event asynchronously.

    The acknowledgement confirms receipt, not completion of your business processing. Do not execute the same business action twice for a duplicate event.
  </Step>
</Steps>

Handle events without relying on arrival order. Follow the identifiers and processing rules in [transaction callbacks](/api-reference/webhooks/transaction-callbacks).

Non-200 responses and transport failures can trigger delivery retries. See [webhooks](/api-reference/webhooks/overview) for delivery behavior.

### Check a received callback

The verifier calculates in your browser without transmitting or persisting your SK. Paste the six headers, raw body, query and correct signature path.

This browser tool accepts only callback URLs with an ASCII path without percent escapes, such as `/pagsmile/webhooks`. Paste the received path unchanged; unsupported paths are rejected before signature calculation.

For escaped URLs, verify on your server using the callback type's [path encoding rule](#callback-path-encoding). Do not decode the URL merely to fit this tool.

It checks the body hash, signature, signature format and nonce format, and displays the timestamp's age. Uppercase signatures fail the 64-character lowercase hexadecimal check.

It does not enforce your timestamp window or record nonces.

Use a server-side verifier with replay protection for your receiver. The browser tool is a diagnostic aid.
