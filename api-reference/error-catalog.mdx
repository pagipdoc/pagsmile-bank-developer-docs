Use this catalog to handle Pagsmile Open API errors by `code`. HTTP 200 alone does not prove that a payment, refund or account opening completed.

## Read the response

Every JSON business result returns HTTP 200 with `code`, `message`, `data` and `time`. When `code` is `200`, read `data` and check the operation's status.

| Response | Meaning | What to do |
| --- | --- | --- |
| HTTP 200, `code` is `200` | API call succeeded | Check the endpoint's completion criteria. |
| HTTP 200, `code` differs from `200` | Business, validation, authentication or system error | Handle the business code below. |
| HTTP 400, `text/plain` body | Unreadable body or invalid JSON | Correct the request body. |
| HTTP 403, `text/plain` body `error code: 1010` | Network edge blocked the client before the API | Send a descriptive `User-Agent`, such as `your-app/1.0`. |
| HTTP 404, 405 or 307 | Unknown path, a method other than `POST`, or a trailing slash | Use `POST` and the exact documented path. |
| HTTP 500, `text/plain` body such as `system error` | Unexpected server failure; original operation outcome unknown | Query the original operation before resubmitting. |
| Timeout or connection loss | Result unknown | Query the original operation before resubmitting. |

HTTP 500 with a plain-text body differs from HTTP 200 with business `code` equal to `500`. Do not parse that plain-text body as JSON.

The network edge returns HTTP 403 with the text `error code: 1010` before the request reaches the API. It can reject a request with no `User-Agent` or with some library defaults, such as `Python-urllib/3.12`. Changing the signature does not fix it.

Use `code` for programmatic decisions and `message` for troubleshooting. A code can have different messages depending on the endpoint and failure.

The tables show default messages and verified alternatives used by documented endpoints. `{{.field}}` contains the failed field at runtime. `4004102` and `4004103` currently return `{{.header}}` and `{{.ip}}` unrendered, so their messages do not name the header or source IP.

Every response includes `xxx-log-id`. Keep this response header when you contact support.

## Validation errors

| Code | Message | Meaning | What to do |
| --- | --- | --- | --- |
| `400` | `Invalid parameter` | Request fails a business validation. | Check the endpoint's request rules. |
| `4000` | `Field {{.field}} is required` | Required field is missing. | Supply the named field. |
| `4001` | `Invalid {{.field}} value` | Field contains an invalid value. | Check the field's accepted values. |
| `4002` | `Invalid {{.field}} format` | Field format is invalid. | Check the field's format. |
| `4003` | `{{.field}} value out of range` | Field is outside the accepted range. | Follow the endpoint's range rules. |
| `4001012` | `Time range must be within 31 days` | Date range is too long. | Split the query into shorter ranges. |

Amounts use decimal strings in BRL, for example `"10.50"`. Follow each endpoint's required fields and amount rules.

## Authentication errors

| Code | Message | Meaning | What to do |
| --- | --- | --- | --- |
| `401` | `User is invalid` | Credential or user context is invalid. | Check the AK and the user's OpenAPI access. |
| `4003008` | `Authentication required` | Required authentication context is missing. | Check the credential and target account. |
| `4004101` | `Authorization is required` | `X-Client-ID` or other authorization context is missing. | Send `X-Client-ID` with your AK. |
| `4004102` | `Invalid {{.header}} header` | `X-Timestamp`, `X-Nonce` or `X-Signature` is missing, or `X-Timestamp` is not numeric. | Check all three headers; the message does not name the header. |
| `4004103` | `IP address has no permission: {{.ip}}` | Source IP is outside the allowlist. | Configure your outbound IP or CIDR. |
| `4004104` | `X-Content-Hash does not match request body` | Declared hash differs from the body. | Hash the exact bytes you send. |
| `4004105` | `X-Timestamp is invalid or expired` | Timestamp falls outside the five-minute window. | Synchronize your clock and use Unix milliseconds. |
| `4004106` | `X-Nonce is invalid or has already been used` | Nonce is already recorded for this AK. | Generate a new nonce for this attempt. |
| `4004107` | `X-Signature is invalid` | Signature verification failed. | Check the SK and signed request. |

A missing `X-Nonce` returns `4004102` with the unrendered template `Invalid {{.header}} header`. A nonce that is already recorded returns `4004106`.

An empty IP allowlist denies all requests. The allowlist accepts exact IP addresses and CIDR ranges.

The API records a nonce for ten minutes per AK before checking the signature. A failed signature still consumes that nonce.

Sign each attempt with a new `X-Nonce` and `X-Timestamp`. Follow [Sign requests](/environments-and-credentials#sign-requests) to include the body and applicable account headers.

## Account and permission errors

| Code | Message | Meaning | What to do |
| --- | --- | --- | --- |
| `4001092` | `Invalid KYC status` | Compliance status does not allow the operation. | Check the account's KYC or KYB status. |
| `4002003` | `The information has been registered` | Onboarding information is already registered. | Query the existing application or account. |
| `4004003` | `Permission denied` | Credential, ownership or account conditions deny access. | Check the endpoint's credential and account requirements. |
| `4004004` | `Not found` | Resource is unavailable in the requested scope. | Check the identifier and ownership. |
| `4004008` | `Account is inactive` | Account cannot perform the operation. | Check account status and payment permissions. |
| `4004010` | `Account not found` | Account lookup failed. | Check the target account identifiers. |

For account-scoped calls, check `X-ISPB` and `X-Account-Number` against the [credential rules](/environments-and-credentials). Permission errors can also indicate a credential type that the endpoint does not accept.

## System and onboarding errors

| Code | Message | Meaning | What to do |
| --- | --- | --- | --- |
| `500` | `System error, please try again later` or `Service temporarily unavailable, please try again later` | API or a dependency could not complete the call. | Check the original operation before retrying. |
| `501` | `Service temporarily unavailable, please try again later` | Required dependency is unavailable. | Check the original result, then follow endpoint retry rules. |
| `502` | `Bank services are currently busy, please try again later` | Bank processing is unavailable or busy. | Query the result before resubmitting. |
| `503` | `This service is temporarily unavailable, please try again later` | Requested service is unavailable. | Check endpoint availability with support. |
| `504` | `Compliance submission status could not be confirmed. The account creation fee was not charged. Retry with the same reference_id.` | Onboarding submission result is unknown. | Retry with the same `reference_id` and a new signature. |

For [managed account creation](/api-reference/onboarding/create-managed-account), `400` can return `Compliance submission was rejected. The account creation fee was not charged. Correct the request and retry with a new reference_id.`

That rejection requires a corrected request and a new `reference_id`. For `504`, keep the same `reference_id`. Neither message reports an account creation fee charge.

## Retries and support

After a timeout, duplicate response or uncertain processing failure, query the original payment, refund or account application. Do not change business identifiers solely because you missed a response.

Follow the endpoint's idempotency rules when resubmitting. Regenerate signature metadata for each attempt, including the timestamp and nonce, and hash the exact body you send.

For an unknown code or unresolved error, contact integration support. Include the environment, endpoint, request time, HTTP status, `code`, `message`, resource identifier and `xxx-log-id`.

Mask sensitive data in the request and response. Do not include your SK.
