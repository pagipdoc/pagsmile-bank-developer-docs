Lists payer-created MED cases for the selected account. Omit an enum filter to include every status; an explicit `0` selects UNSPECIFIED.

## Before you call

<Tabs>
  <Tab title="ACCOUNT" icon="building-columns">
    The query uses the account bound to your AK. Omit both account-target headers, or send both matching that account.
  </Tab>
  <Tab title="USER" icon="user">
    Send `X-ISPB` and `X-Account-Number` for an account you own. Include both headers in the [signature](/environments-and-credentials#sign-requests).
  </Tab>
  <Tab title="PLATFORM" icon="server">
    <Warning>PLATFORM credentials cannot call this endpoint. Use an ACCOUNT or USER credential.</Warning>
  </Tab>

## Scope and filters

This list includes only payer-created cases. It excludes receiver-side notification cases and cases created through the administrative flow.

Filters are combined with AND. Nonempty identifiers use exact matching; omitted or empty identifiers leave that filter unset.

Omit enum filters to include all values. Sending `0` filters for UNSPECIFIED, rather than disabling the filter.

Time bounds are inclusive and use Unix milliseconds (UTC). A zero or negative bound is ignored; reversed positive bounds produce no matches.

## Pagination

Results are ordered by creation time, newest first. `page` defaults to `1`; `page_size` defaults to `20` when omitted or nonpositive.

Send a `page_size` from `1` to `100`. Larger values query 100 items but remain unchanged in `data.page.page_size` and the `total_pages` calculation.

Keep the same filters and account selection when requesting the next page.

## Read the result

When `code` is `200`, read `data.items` and the pagination metadata. An empty list means no visible records matched the filters.

Open the matching case with `data.items[].case_id`. The summary `amount` is the amount requested for recovery, not proof of returned funds.

## Query retries

If a query fails or times out, repeat the same lookup rather than creating a new case. Sign each attempt with new `X-Nonce` and `X-Timestamp` values.

Read the business `code` even when HTTP status is `200`. Include the response header `xxx-log-id` when contacting support.
