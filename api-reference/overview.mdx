Use the Pagsmile Open API to manage accounts, receive Pix and send payments. Read `code` before `data`: HTTP `200` alone does not prove a payment or refund completed.

## Request and response contract

Call every v3 endpoint with `POST` and a JSON body. Send `Content-Type: application/json`, including when the endpoint requires an empty object, such as `{}` for `/v3/bank_account`.

Send a descriptive `User-Agent`, such as `your-app/1.0`. The network edge can reject a missing or default library value with HTTP 403 before the API reads the request.

Choose your base URL and sign the request as described in [Environments and credentials](/environments-and-credentials#sign-requests).

| Environment | Base URL |
| --- | --- |
| Sandbox | `https://ebanking-openapi-sandbox.pagsmile.com.br` |
| Production | `https://ebanking-openapi.pagsmile.com.br` |

JSON results use the envelope `{code, message, data, time}`.

| Field | How to read it |
| --- | --- |
| `code` | Integer business result. `200` means the call succeeded; other codes describe errors. |
| `message` | Result message. Use `code` to select your error-handling branch. |
| `data` | Endpoint-specific result. Read the endpoint's schema and status rules before acting. |
| `time` | Server timestamp as an integer in Unix milliseconds. |

All JSON results return HTTP `200`, including validation, authentication, business and system errors. A business `code` of `400` or `500` is not the HTTP status.

Unreadable bodies and invalid JSON return HTTP `400` with a `text/plain` body. Handle these transport errors separately from the JSON envelope.

An unexpected server failure can return HTTP `500` with a `text/plain` body such as `system error`. Do not parse it as the JSON envelope. For a money-moving operation, query the original result before resubmitting.

Save the response header `xxx-log-id` and include it when you contact support.

## Before you call

Choose credentials for the endpoint family. Account-target headers select an account only where the endpoint accepts them.

| Endpoint family | Credentials | Account selection |
| --- | --- | --- |
| Managed-account onboarding | USER | Omit account-target headers. |
| Accounts, Pix keys, pay-ins, payouts, refunds and MED | ACCOUNT or USER | Bound account or USER-owned target. |
| Webhook subscriptions | ACCOUNT, USER or PLATFORM | Rules depend on the subscription scope. |

<Tabs>
  <Tab title="ACCOUNT" icon="building-columns">
    For account-scoped endpoints, use the account bound to your credential. You can omit `X-ISPB` and `X-Account-Number`. If you send them, send both and match the bound account.

    Webhook subscriptions use the account scope. ACCOUNT credentials cannot call managed-account onboarding endpoints.
  </Tab>
  <Tab title="USER" icon="user">
    For account-scoped endpoints, send both `X-ISPB` and `X-Account-Number` for an account owned by the USER. Include both headers in the [signature](/environments-and-credentials#sign-requests).

    Omit account-target headers for managed-account onboarding and USER-scoped webhook subscriptions. A subscription may require `account_number` in the request body; follow its endpoint rules.
  </Tab>
  <Tab title="PLATFORM" icon="server">
    PLATFORM credentials support platform-scoped webhook subscriptions. Omit account-target headers and check the allowed events in the [subscription reference](/api-reference/webhooks/create-event-subscription).

    <Warning>PLATFORM credentials cannot call the account-scoped or managed-account onboarding endpoints listed here. Use ACCOUNT or USER as required by the endpoint.</Warning>
  </Tab>
</Tabs>

The credential scope does not replace the endpoint's account, ownership or status checks. Read those prerequisites before submitting a request.

## Amounts and timestamps

Send monetary amounts as decimal strings in BRL, for example `"10.50"`, rather than JSON numbers. Follow each endpoint's rules for positive amounts, optional amounts and decimal precision.

Numeric timestamps, such as `time`, `created_at` and `snapshot_timestamp`, use Unix milliseconds. Preserve them as integers and convert them to your display time zone when needed.

Read duration and date fields separately. Do not treat an expiration duration as a Unix timestamp.

## Pagination

Pagination is endpoint-specific. Do not assume that every list endpoint accepts a page number or returns a total.

| List | Pagination contract |
| --- | --- |
| [Managed accounts](/api-reference/onboarding/list-managed-accounts) | Send a `page` object with `page` and `page_size`. The response includes `data.page` pagination metadata. |
| [Account statement](/api-reference/accounts/get-account-statement) | Send `page_size`. Continue with the returned `data.cursor` and preserve `data.snapshot_timestamp` in the next request. |

Statement results use descending time order. Match the entry to your transaction; do not assume the first entry is the payment you want.

For [MED cases](/api-reference/med/list-med-cases) and [infraction reports](/api-reference/med/list-infraction-reports), use the pagination fields documented on each endpoint page.
