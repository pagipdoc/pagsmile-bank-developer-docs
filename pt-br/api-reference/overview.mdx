Use a Pagsmile Open API para gerenciar contas, receber Pix e enviar pagamentos. Leia `code` antes de `data`: HTTP `200` não comprova a conclusão de um pagamento ou de uma devolução.

## Contrato de requisições e respostas

Chame todos os endpoints v3 com `POST` e um corpo JSON. Envie `Content-Type: application/json`, inclusive quando o endpoint exigir um objeto vazio, como `{}` para `/v3/bank_account`.

Envie um `User-Agent` descritivo, como `your-app/1.0`. A borda da rede pode recusar um valor ausente ou padrão de biblioteca com HTTP 403 antes de a API ler a requisição.

Escolha a URL base e assine a requisição conforme [Ambientes e credenciais](/pt-br/environments-and-credentials#assinar-requisições).

| Ambiente | URL base |
| --- | --- |
| Sandbox | `https://ebanking-openapi-sandbox.pagsmile.com.br` |
| Produção | `https://ebanking-openapi.pagsmile.com.br` |

Os resultados JSON usam o envelope `{code, message, data, time}`.

| Campo | Como interpretar |
| --- | --- |
| `code` | Código inteiro do resultado de negócio. `200` indica sucesso na chamada; os demais códigos descrevem erros. |
| `message` | Mensagem do resultado. Use `code` para decidir como tratar o erro. |
| `data` | Resultado específico do endpoint. Consulte o schema e as regras de status antes de agir. |
| `time` | Horário do servidor como inteiro em milissegundos Unix. |

Todos os resultados JSON retornam HTTP `200`, inclusive erros de validação, autenticação, negócio e sistema. Um `code` de `400` ou `500` não é o status HTTP.

Corpos que não podem ser lidos e JSON inválido retornam HTTP `400` com corpo `text/plain`. Trate esses erros de transporte separadamente do envelope JSON.

Uma falha inesperada do servidor pode retornar HTTP `500` com corpo `text/plain`, como `system error`. Não interprete esse corpo como o envelope JSON. Em operações que movimentam recursos, consulte o resultado original antes de reenviar.

Guarde o cabeçalho de resposta `xxx-log-id` e informe-o ao entrar em contato com o suporte.

## Antes de chamar

Escolha as credenciais conforme a família do endpoint. Os cabeçalhos de seleção de conta só selecionam uma conta quando o endpoint os aceita.

| Família de endpoints | Credenciais | Seleção de conta |
| --- | --- | --- |
| Onboarding de contas gerenciadas | USER | Omita os cabeçalhos de seleção de conta. |
| Contas, chaves Pix, recebimentos, pagamentos, devoluções e MED | ACCOUNT ou USER | Conta vinculada ou conta pertencente ao USER. |
| Assinaturas de eventos | ACCOUNT, USER ou PLATFORM | As regras dependem do escopo da assinatura de eventos. |

<Tabs>
  <Tab title="ACCOUNT" icon="building-columns">
    Nos endpoints de conta, use a conta vinculada à sua credencial. Você pode omitir `X-ISPB` e `X-Account-Number`. Se enviar esses cabeçalhos, envie ambos com os dados da conta vinculada.

    As assinaturas de eventos usam o escopo da conta. Credenciais ACCOUNT não podem chamar endpoints de onboarding de contas gerenciadas.
  </Tab>
  <Tab title="USER" icon="user">
    Nos endpoints de conta, envie `X-ISPB` e `X-Account-Number` de uma conta que pertença ao USER. Inclua ambos na [assinatura](/pt-br/environments-and-credentials#assinar-requisições).

    Omita os cabeçalhos de seleção de conta no onboarding de contas gerenciadas e nas assinaturas de eventos com escopo USER. A assinatura de eventos pode exigir `account_number` no corpo da requisição; siga as regras do endpoint.
  </Tab>
  <Tab title="PLATFORM" icon="server">
    Credenciais PLATFORM permitem assinaturas de eventos com escopo da plataforma. Omita os cabeçalhos de seleção de conta e confira os eventos permitidos na [referência de assinaturas de eventos](/pt-br/api-reference/webhooks/create-event-subscription).

    <Warning>Credenciais PLATFORM não podem chamar os endpoints de conta ou de onboarding de contas gerenciadas listados aqui. Use ACCOUNT ou USER conforme o endpoint.</Warning>
  </Tab>
</Tabs>

O escopo da credencial não substitui as verificações de conta, titularidade ou status do endpoint. Leia esses requisitos antes de enviar uma requisição.

## Quantias e horários

Envie quantias monetárias como strings decimais em BRL, por exemplo `"10.50"`, e não como números JSON. Siga as regras de cada endpoint para quantias positivas, opcionais e precisão decimal.

Timestamps numéricos, como `time`, `created_at` e `snapshot_timestamp`, usam milissegundos Unix. Preserve-os como inteiros e converta-os para o fuso horário de exibição quando necessário.

Consulte separadamente os campos de duração e de data. Não interprete uma duração de validade como um timestamp Unix.

## Paginação

A paginação varia conforme o endpoint. Não presuma que toda consulta de lista aceita um número de página ou retorna um total.

| Lista | Contrato de paginação |
| --- | --- |
| [Contas gerenciadas](/pt-br/api-reference/onboarding/list-managed-accounts) | Envie um objeto `page` com `page` e `page_size`. A resposta inclui os metadados de paginação em `data.page`. |
| [Extrato da conta](/pt-br/api-reference/accounts/get-account-statement) | Envie `page_size`. Continue com o `data.cursor` retornado e preserve `data.snapshot_timestamp` na próxima requisição. |

Os resultados do extrato seguem a ordem decrescente de horário. Localize o lançamento correspondente à sua transação; não presuma que o primeiro seja o pagamento desejado.

Para [casos MED](/pt-br/api-reference/med/list-med-cases) e [notificações de infração](/pt-br/api-reference/med/list-infraction-reports), use os campos de paginação documentados na página de cada endpoint.
