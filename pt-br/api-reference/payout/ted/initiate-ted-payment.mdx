Envie uma TED para um banco com ISPB diferente do ISPB do pagador. Um envio bem-sucedido aceita o pagamento para processamento assíncrono, sem confirmar a conclusão.

| Credenciais | Chave de duplicidade | Resultado |
| --- | --- | --- |
| ACCOUNT, USER | `merchant_order_id` | Assíncrono |

## Antes de chamar

<Tabs>
  <Tab title="ACCOUNT" icon="building-columns">
    Use a credencial vinculada à conta do pagador. Omita `X-ISPB` e `X-Account-Number`, ou envie ambos com os dados dessa conta.
  </Tab>
  <Tab title="USER" icon="user">
    Envie `X-ISPB` e `X-Account-Number` de uma conta pertencente ao USER. Esses cabeçalhos selecionam o pagador, não o recebedor.

    Inclua os dois cabeçalhos na [assinatura](/pt-br/environments-and-credentials#assinar-requisições).
  </Tab>
  <Tab title="PLATFORM" icon="server">
    <Warning>Credenciais PLATFORM não podem chamar este endpoint. Use uma credencial ACCOUNT ou USER da conta do pagador.</Warning>
  </Tab>
</Tabs>

A conta do pagador precisa estar habilitada para enviar pagamentos. Confira os dados bancários e o documento do recebedor antes do envio.

## Preparar o pagamento

Envie o valor do pagamento como string decimal em BRL, como `"10.00"`. Ele deve ser positivo e representável exatamente com duas casas decimais.

O banco do recebedor deve ser diferente do banco do pagador. Para contas elegíveis da mesma instituição, use [Iniciar transferência interna](/pt-br/api-reference/payout/book-transfer/initiate-internal-transfer).

Os limites de pagamento configurados também se aplicam à TED. Uma rejeição por limite retorna o código de negócio `4001998`; esta página não define um limite numérico universal.

## Janelas de processamento

O envio de TED ao banco segue o calendário bancário brasileiro em `America/Sao_Paulo`. O envio ao banco é interrompido 65 minutos antes do fechamento da janela ativa.

Se a janela estiver fechada e houver uma próxima janela ativa, o pagamento aceito é agendado para essa janela. Continue acompanhando o pagamento original em vez de enviá-lo novamente.

## Interpretar o resultado

Todos os resultados de negócio em JSON retornam HTTP `200`. Leia `code` antes de usar `data`; apenas corpos ilegíveis ou JSON inválido retornam HTTP `400` com texto simples.

Quando `code` é `200`, salve `data.txn_id` e o `merchant_order_id` original. Use o ID da transação salvo para [consultar o pagamento](/pt-br/api-reference/payout/get-payment-status).

| Status | Significado | O que comprova | Próximo passo |
| --- | --- | --- | --- |
| `5` PROCESSING | Aceito para processamento | Apenas o envio | Consulte o pagamento original |
| `1` PENDING | Pendente | Não é status final | Continue acompanhando o pagamento original |
| `2` COMPLETED | Pagamento concluído | Conclusão confirmada | Concilie o pagamento |
| `3` FAILED | Pagamento falhou | Falha registrada | Confira os detalhes |
| `4` CANCELLED | Pagamento cancelado | Cancelamento registrado | Confira os detalhes |

O envio retorna `5` (PROCESSING). Consulte o status ou os detalhes no mesmo contexto da conta do pagador antes de considerar o pagamento concluído.

No Sandbox, um TED enviado fora de uma janela de processamento retornou `1` (PENDING) nas consultas de status seguintes. Um ISPB do recebedor igual ao do pagador retorna `4001` com a mensagem `Invalid payee.bank_code value`. Um `payee.bank_code` que não corresponde a nenhum banco do diretório de participantes retorna `400` com a mensagem `Payee bank code is invalid`.

A resposta do envio retorna `null` em `payee`, `payer` e `error`. Obtenha os dados dos participantes em [Consultar detalhes do pagamento](/pt-br/api-reference/payout/get-payment-details).

## Repetições e duplicidades

Use um ID de pedido único entre contas e operações do mesmo ambiente. IDs aceitos ficam reservados por até 48 horas.

<AccordionGroup>
  <Accordion title="O resultado do envio é desconhecido" icon="clock-rotate-left">
    Após um timeout, uma falha de rede ou um erro de sistema, verifique o pagamento original antes de reenviar. Uma consulta imediata pode não encontrar a transação.

    Consulte novamente em vez de criar outro pagamento. Se você não recebeu `txn_id`, guarde o ID do pedido e o cabeçalho de resposta `xxx-log-id` para o suporte.
  </Accordion>
  <Accordion title="O ID do pedido já está reservado" icon="clone">
    Uma nova requisição com um `merchant_order_id` ainda retido retorna `4001013` (Already processed). Ela não repete a resposta de sucesso original.

    Alterar o ID do pedido pode criar outro pagamento. Veja [Visão geral de pagamentos](/pt-br/api-reference/payout/overview) para tratar um resultado desconhecido.
  </Accordion>
  <Accordion title="Falha na assinatura" icon="signature">
    Assine cada tentativa com novos `X-Nonce` e `X-Timestamp`. O nonce é consumido mesmo se a assinatura falhar.

    Veja [erros de autenticação](/pt-br/api-reference/error-catalog#erros-de-autenticação).
  </Accordion>
</AccordionGroup>
