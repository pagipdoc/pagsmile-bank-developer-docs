Transfira entre contas internas diferentes da mesma instituição. O ISPB do recebedor deve ser igual ao do pagador, e o recebedor precisa estar habilitado para receber pagamentos.

## Fluxo da transferência

<Steps>
  <Step title="Preparar a transferência">
    Confira a conta que receberá os recursos e os dados do documento do titular. Crie e guarde o `merchant_order_id` antes de enviar a transferência.
  </Step>
  <Step title="Enviar a transferência interna">
    Chame [Iniciar transferência interna](/pt-br/api-reference/payout/book-transfer/initiate-internal-transfer). Quando `code` é `200`, salve `data.txn_id`; a transferência foi aceita para processamento assíncrono.
  </Step>
  <Step title="Confirmar o resultado">
    Use o ID salvo como `txn_id` em [Consultar status do pagamento](/pt-br/api-reference/payout/get-payment-status) ou [Consultar detalhes do pagamento](/pt-br/api-reference/payout/get-payment-details).

    Mantenha o contexto da conta do pagador nessas consultas. Uma resposta com `txn_status` igual a `2` (COMPLETED) confirma a conclusão.
  </Step>
</Steps>

## Endpoints

| Endpoint | O que faz |
| --- | --- |
| [Iniciar transferência interna](/pt-br/api-reference/payout/book-transfer/initiate-internal-transfer) | Envia uma transferência entre contas internas. |
| [Consultar status do pagamento](/pt-br/api-reference/payout/get-payment-status) | Consulta o status atual da transação. |
| [Consultar detalhes do pagamento](/pt-br/api-reference/payout/get-payment-details) | Retorna os dados da transferência e dos participantes. |

## Antes de chamar

<Tabs>
  <Tab title="ACCOUNT" icon="building-columns">
    Use a credencial vinculada à conta do pagador. Omita `X-ISPB` e `X-Account-Number`, ou envie ambos com os dados dessa conta.
  </Tab>
  <Tab title="USER" icon="user">
    Envie `X-ISPB` e `X-Account-Number` de uma conta pertencente ao USER. Esses cabeçalhos selecionam o pagador, não o recebedor.

    Inclua os dois cabeçalhos na [assinatura](/pt-br/environments-and-credentials#assinar-requisições).
  </Tab>
  <Tab title="PLATFORM" icon="server">
    <Warning>Credenciais PLATFORM não podem enviar essas transferências. Use uma credencial ACCOUNT ou USER da conta do pagador.</Warning>
  </Tab>
</Tabs>

A conta do pagador precisa estar habilitada para enviar pagamentos. A transferência interna usa os limites configurados para o pagador, considerando o tipo de documento do recebedor.

## Contas elegíveis para recebimento

A conta do recebedor deve existir, estar ativa, estar habilitada para receber pagamentos e não ter encerramento em andamento.

O ISPB, o número da conta, a agência e o tipo de conta devem corresponder à requisição. O número e o tipo do documento devem corresponder ao titular.

Use uma conta diferente da conta do pagador. Este endpoint não transfere para outra instituição; use [TED](/pt-br/api-reference/payout/ted/overview) nesse caso.

## Status

Quando `code` é `200` no envio, `data.txn_status` é `5` (PROCESSING). A aceitação não comprova que a conta do recebedor recebeu o crédito.

| Status | Significado | O que comprova | Próximo passo |
| --- | --- | --- | --- |
| `5` PROCESSING | Aceito para processamento | Apenas o envio | Consulte a transferência original |
| `2` COMPLETED | Transferência concluída | Conclusão confirmada | Concilie a transferência |
| `3` FAILED | Transferência falhou | Falha registrada | Confira os detalhes |
| `4` CANCELLED | Transferência cancelada | Cancelamento registrado | Confira os detalhes |

Esses são resultados que você deve consultar, não uma garantia de que toda transferência passa por cada status.

## Repetições e duplicidades

Use um ID de pedido único entre contas e operações do mesmo ambiente. IDs aceitos ficam reservados por até 48 horas.

Um novo envio com um `merchant_order_id` ainda retido retorna `4001013`. A API rejeita a duplicidade em vez de repetir a resposta de sucesso original.

Após um timeout, uma falha de rede ou um erro de sistema, verifique a transferência original antes de reenviar. Uma consulta imediata pode não encontrar a transação.

Consulte novamente em vez de criar outra transferência. Se você não recebeu `txn_id`, guarde o ID do pedido original e o cabeçalho de resposta `xxx-log-id` para o suporte.

Veja [Visão geral de pagamentos](/pt-br/api-reference/payout/overview) para tratar um resultado de envio desconhecido.
