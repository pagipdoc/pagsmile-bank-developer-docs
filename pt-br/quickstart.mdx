Use este guia para cadastrar sua conta Pagsmile, preparar o acesso ao Sandbox na Central do desenvolvedor e enviar sua primeira consulta assinada pelo seu servidor.

## Cadastrar sua conta

Use o canal de cadastro indicado para sua integração. As capturas de tela ilustram o cadastro, a verificação e a ativação da conta.

Siga o formulário atual para documentos, verificações e instruções de ativação. As capturas não definem critérios de aprovação nem a validade dos códigos de verificação.

## Habilitar o acesso à API

Após a abertura e a ativação da conta de produção, acesse sua conta de teste do Sandbox pela **Central do desenvolvedor** no [portal Banking](https://banking.pagsmile.com.br/login).

<Info>
  Estas etapas descrevem o fluxo da próxima versão da Central do desenvolvedor. Siga-as quando a **Central do desenvolvedor** estiver disponível no seu portal Banking.
</Info>

<Steps>
  <Step title="Abrir a Central do desenvolvedor">
    Entre no portal Banking com seu acesso de produção e selecione **Central do desenvolvedor** no menu lateral. Abra **Visão geral** e confira o indicador **Sandbox** e a conta de teste exibida.

    A conta do Sandbox é exclusiva para API e não tem acesso separado ao portal. As operações do Sandbox na Central do desenvolvedor não exigem MFA, senha de pagamento nem outro código de verificação. Os requisitos de autenticação para entrar no Banking continuam valendo.
  </Step>
  <Step title="Aguardar a preparação da conta de teste">
    A Pagsmile prepara automaticamente uma conta de teste no Sandbox e suas chaves de acesso (AK) e secreta (SK) do tipo ACCOUNT após a ativação da conta de produção. Você não precisa criar outra conta nem gerar o primeiro par de chaves.

    Se a preparação estiver em andamento, volte à **Visão geral** mais tarde. Se ela falhar, siga a ação de recuperação exibida. Confira a conta de teste antes de continuar; trocar de conta de produção não altera a conta vinculada às credenciais de teste.
  </Step>
  <Step title="Permitir o acesso à API do Sandbox">
    Abra **Credenciais de teste**. O titular pode selecionar **Ver e copiar credenciais** e conferir se a credencial está **Ativa**.

    Em **IPs permitidos**, adicione o IP público de saída de cada origem dos testes:

    - **Central do desenvolvedor no portal Banking:** adicione o IP público de saída do computador que você está usando à lista de IPs permitidos da API do Sandbox antes de testar.
    - **Seu servidor:** adicione o IP público de saída do servidor antes de enviar requisições à API pela sua integração.

    Se usar uma VPN ou rede corporativa, permita o IP público por onde sai o tráfego dos testes. Não informe o endereço privado do computador na rede local. Confira o IP novamente se mudar de rede ou de conexão VPN.

    Siga [Configurar acesso à API](/pt-br/api-access-setup) para guardar o par de chaves do Sandbox, identificar o IP correto e configurar seu servidor. Essa página também permite informar credenciais do Sandbox e testar nesta documentação, se você preferir.

    Se seu usuário de equipe não puder gerenciar credenciais, peça ao titular que conclua esta etapa. Você pode consultar as credenciais do Sandbox novamente sem renová-las.
  </Step>
</Steps>

## Explorar APIs na Central do desenvolvedor

Antes de testar, confirme que o IP público de saída do computador que você está usando está salvo em **Credenciais de teste → IPs permitidos** para a API do Sandbox.

Em **Visão geral**, encontre **Teste sua integração**. Selecione **Contas e saldos** em **Cenário de integração** e depois **Testar no sandbox** para `POST /v3/bank_account`.

O formulário lê os campos e exemplos da documentação da API e preenche o contexto da conta de teste. Esta consulta usa o corpo `{}`. Nas outras operações, confira os valores de exemplo e informe os campos de negócio necessários para seu teste. Você pode examinar a requisição em formulário ou JSON.

Uma resposta identificada como exemplo ou simulação não comprova que uma chamada à API funcionou. Mesmo uma chamada bem-sucedida pela Central do desenvolvedor não verifica o IP nem o código de assinatura do seu servidor. Continue abaixo para verificar sua própria integração.

## Enviar sua primeira requisição assinada

Envie `POST /v3/bank_account` pelo seu servidor para consultar a conta de teste do Sandbox. Use o par de chaves ACCOUNT de **Credenciais de teste** e o objeto JSON vazio `{}`.

A credencial seleciona a conta, por isso os exemplos omitem `X-ISPB` e `X-Account-Number`. Se sua integração usa credenciais USER provisionadas separadamente, siga [Credenciais e seleção de conta](/pt-br/environments-and-credentials#credenciais-e-seleção-de-conta). Credenciais PLATFORM não podem chamar este endpoint.

<Steps>
  <Step title="Confirmar o destino Sandbox">
    Use `https://ebanking-openapi-sandbox.pagsmile.com.br` e o par de chaves ACCOUNT do Sandbox. Confira se o IP de saída do servidor está na lista de IPs permitidos dessa credencial.

    A URL base de Produção, `https://ebanking-openapi.pagsmile.com.br`, é exibida apenas para consulta. A entrada de credenciais e os testes online desta documentação são exclusivos do Sandbox.
  </Step>
  <Step title="Preparar o exemplo">
    Defina `PAGSMILE_AK` e `PAGSMILE_SK` no ambiente do servidor. Os exemplos usam o Sandbox por padrão; se definir `PAGSMILE_BASE_URL`, mantenha a URL do Sandbox neste guia. [Configurar acesso à API](/pt-br/api-access-setup) gera essas variáveis para bash e PowerShell.

    Use o ambiente de execução indicado na aba da linguagem. Não incorpore credenciais ao código do navegador, ao controle de versão ou a mensagens de suporte.
  </Step>
  <Step title="Assinar e enviar os mesmos bytes">
    Assine o caminho, os cabeçalhos obrigatórios e o corpo exato da requisição com HMAC-SHA256. Não reformate o JSON depois de assinar.

    Use novos `X-Nonce` e `X-Timestamp` a cada tentativa, inclusive após um erro de assinatura. Confira o IP do servidor na lista de permissões.

    Use a [ferramenta de assinatura](/pt-br/environments-and-credentials#assinar-requisições) para conferir uma requisição antes de enviar.
  </Step>
  <Step title="Interpretar o resultado de negócio">
    Leia `code` antes de usar `data`. Quando `code` é `200`, a consulta da conta funcionou; isso não comprova a conclusão de um pagamento.

    Todo resultado de negócio em JSON retorna HTTP 200, inclusive erros. Um corpo ilegível ou JSON inválido retorna HTTP 400 com texto simples.

    Veja [Dados da conta](/pt-br/api-reference/accounts/get-account-balance) para os campos retornados e [Erros de autenticação](/pt-br/api-reference/error-catalog#erros-de-autenticação) para requisições recusadas.

    Inclua o cabeçalho de resposta `xxx-log-id` nas solicitações de suporte, sem sua SK nem as credenciais completas.
  </Step>
</Steps>

Escolha uma linguagem. Cada exemplo assina e envia o mesmo corpo `{}`, inclui `X-Content-Hash` e exibe a resposta.

Defina `PAGSMILE_TIMEOUT_SECONDS` como um inteiro positivo; os exemplos usam 30 segundos por padrão. No Python, o timeout vale para operações bloqueantes de socket; nos demais exemplos, limita a duração total da requisição.

Falhas de conexão e timeouts são exibidos na saída de erro e encerram o programa com erro, separadamente dos resultados de negócio em JSON. Os exemplos não repetem a requisição automaticamente.

<CodeGroup>

```bash cURL
# Requer curl, OpenSSL e Python 3. Exporte PAGSMILE_SK; o auxiliar HMAC lê a chave do ambiente, nunca dos argumentos de linha de comando. Defina PAGSMILE_AK e PAGSMILE_SK. PAGSMILE_BASE_URL usa o Sandbox por padrão.
BASE_URL="${PAGSMILE_BASE_URL:-https://ebanking-openapi-sandbox.pagsmile.com.br}"
REQ_PATH="/v3/bank_account"
TIMEOUT_SECONDS="${PAGSMILE_TIMEOUT_SECONDS:-30}"
case "$TIMEOUT_SECONDS" in
  ''|*[!0-9]*|0*) echo 'PAGSMILE_TIMEOUT_SECONDS must be a positive integer' >&2; exit 1 ;;
esac
BODY='{}'

# Assine exatamente os bytes enviados. Use novos nonce e timestamp a cada tentativa.
TS=$(( $(date +%s) * 1000 ))
NONCE=$(openssl rand -hex 16)
HASH=$(printf '%s' "$BODY" | openssl dgst -sha256 -hex | sed 's/^.* //')
STRING_TO_SIGN=$(printf 'POST\n%s\n\ncontent-type:application/json\nx-client-id:%s\nx-content-hash:%s\nx-nonce:%s\nx-timestamp:%s\n%s\n%s\n%s' \
  "$REQ_PATH" "$PAGSMILE_AK" "$HASH" "$NONCE" "$TS" "$HASH" "$TS" "$NONCE")
SIGNATURE=$(printf '%s' "$STRING_TO_SIGN" | python3 -c 'import hashlib, hmac, os, sys; print(hmac.new(os.environ["PAGSMILE_SK"].encode("utf-8"), sys.stdin.buffer.read(), hashlib.sha256).hexdigest())')

curl -sS --connect-timeout "$TIMEOUT_SECONDS" --max-time "$TIMEOUT_SECONDS" -X POST "$BASE_URL$REQ_PATH" \
  -H "Content-Type: application/json" \
  -H "User-Agent: your-app/1.0" \
  -H "X-Client-ID: $PAGSMILE_AK" \
  -H "X-Timestamp: $TS" \
  -H "X-Nonce: $NONCE" \
  -H "X-Content-Hash: $HASH" \
  -H "X-Signature: $SIGNATURE" \
  --data-raw "$BODY"
```

```python Python
# Defina PAGSMILE_AK e PAGSMILE_SK. PAGSMILE_BASE_URL usa o Sandbox por padrão.

if TIMEOUT_SECONDS <= 0:
    sys.exit("PAGSMILE_TIMEOUT_SECONDS must be a positive integer")
```

```java Java
    public static void main(String[] args) throws Exception {
        String baseUrl = System.getenv().getOrDefault("PAGSMILE_BASE_URL", "https://ebanking-openapi-sandbox.pagsmile.com.br");
```
