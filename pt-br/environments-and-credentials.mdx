A Pagsmile Open API autentica requisições com uma chave de acesso (AK) e uma chave secreta (SK). Assine os bytes exatos do corpo enviado e verifique a assinatura dos callbacks antes de processar os eventos.

## Ambientes

Acrescente o caminho do endpoint à URL base do ambiente. Use o par de credenciais correspondente.

| Ambiente | URL base |
| --- | --- |
| Sandbox | `https://ebanking-openapi-sandbox.pagsmile.com.br` |
| Produção | `https://ebanking-openapi.pagsmile.com.br` |

Use o Sandbox durante a integração. Ao migrar para Produção, altere a URL base e as credenciais juntas.

## Credenciais e seleção de conta

Envie a AK em `X-Client-ID`. Mantenha a SK no seu servidor e use-a para calcular assinaturas; não a envie nas requisições.

Use uma credencial ativa. Para credenciais ACCOUNT e USER, o acesso à OpenAPI do usuário titular também precisa estar habilitado.

<Tabs>
  <Tab title="ACCOUNT" icon="building-columns">
    A credencial está vinculada a uma conta. Nas operações sobre contas, omita `X-ISPB` e `X-Account-Number` para usar essa conta.

    Se você enviar os cabeçalhos de conta, informe os dois com valores não vazios que correspondam à conta vinculada. Essa credencial não permite selecionar outra conta.
  </Tab>
  <Tab title="USER" icon="user">
    Nas operações sobre contas, envie `X-ISPB` e `X-Account-Number` de uma conta que você tenha autorização para acessar. Inclua ambos na assinatura.

    Nas operações de contas gerenciadas e assinaturas de eventos com escopo USER, omita os dois cabeçalhos de conta. Essas operações usam o titular da credencial.
  </Tab>
  <Tab title="PLATFORM" icon="server">
    Use essa credencial somente nos endpoints que permitem acesso PLATFORM. Siga os requisitos de cabeçalhos de cada endpoint.

    <Warning>Credenciais PLATFORM não podem chamar endpoints de pagamento, saldo ou chaves Pix com escopo de conta. Use uma credencial ACCOUNT ou USER nessas operações.</Warning>
  </Tab>
</Tabs>

Preserve os zeros à esquerda nos identificadores de conta. O <Tooltip tip="Identificador do Sistema de Pagamentos Brasileiro: identificador da instituição usado na seleção da conta bancária.">ISPB</Tooltip> identifica a instituição; `X-Account-Number` identifica a conta.

Enviar apenas um cabeçalho de conta, um par vazio ou uma conta não autorizada causa falha na seleção. O resultado tem `code` igual a `4004003` (`Permission denied`).

Veja [modelos de conta](/pt-br/account-models) para entender a relação entre usuários e contas. Confira as credenciais permitidas por cada endpoint antes de chamá-lo.

## Lista de IPs permitidos

Configure o IP de saída que seu servidor usa para acessar a API. A lista aceita endereços IP exatos e intervalos CIDR separados por vírgulas.

Use [Configurar acesso à API](/pt-br/api-access-setup) para descobrir seu IP público, atualizar a **Lista de IPs Permitidos** no painel e conferir cada entrada. A API compara entradas IPv6 exatas como texto, e o campo do painel remove letras; se o seu IPv6 contém `a` a `f`, chame a API por IPv4 e permita o endereço IPv4.

Uma lista vazia bloqueia todas as requisições. Se o IP de origem não corresponder a nenhuma entrada, a API retorna `4004103`. A mensagem atual é o modelo sem substituição `IP address has no permission: {{.ip}}` e não mostra o seu IP.

O Playground de cada página da API envia as requisições diretamente do seu navegador, então a API confere o IP público deste computador. Seus servidores acessam a API pelos próprios endereços. Para testar pela documentação, permita também o endereço deste computador. Veja [Usar a ferramenta de assinatura](#usar-a-ferramenta-de-assinatura).

## Assinar requisições

Todos os endpoints v3 usam `POST` com corpo JSON. Defina `Content-Type` como `application/json` e use o caminho e os campos documentados para o endpoint.

| Cabeçalho | O que enviar |
| --- | --- |
| `Content-Type` | `application/json`. Participa da assinatura. |
| `X-Client-ID` | Sua AK. Obrigatório. |
| `X-Timestamp` | Horário Unix atual em milissegundos, como string de inteiro decimal. Obrigatório. |
| `X-Nonce` | Um identificador aleatório novo para cada tentativa. Obrigatório. |
| `X-Content-Hash` | SHA-256 do corpo bruto em hexadecimal minúsculo. Opcional nas requisições à API. |
| `X-Signature` | Assinatura HMAC-SHA256 com 64 caracteres hexadecimais minúsculos. Obrigatório. |

A API aceita uma diferença de cinco minutos no timestamp. Ela registra cada par de AK e nonce por dez minutos antes de verificar a assinatura.

Gere novos nonce e timestamp a cada tentativa, inclusive após falhas de autenticação. O nonce é consumido mesmo quando a assinatura falha.

O nonce protege uma requisição contra replay. Ele não substitui a chave de idempotência do endpoint; siga as regras de repetição de cada operação.

### Montar a string a ser assinada

<Steps>
  <Step title="Calcular o hash do corpo">
    Serialize o JSON uma vez. Calcule o SHA-256 dos bytes exatos que você enviará e codifique o resultado em hexadecimal minúsculo.

    Calcule esse hash mesmo se omitir `X-Content-Hash`. Se você enviar o cabeçalho, ele precisa corresponder ao hash do corpo.

    Em `POST /v3/bank_account`, envie o objeto JSON `{}`. Seu hash é diferente do hash de um corpo vazio.
  </Step>
  <Step title="Preparar o caminho e a query string">
    Use o caminho da requisição após a decodificação de URL, sem protocolo, domínio, query string ou fragmento. Decodifique os escapes percentuais uma vez.

    Preserve o caminho resultante, sem normalizar ou recodificar. Para os caminhos ASCII documentados, use o caminho sem alterações.

    Ordene os nomes dos parâmetros de consulta em ordem lexicográfica. Preserve a ordem original dos valores quando um nome se repetir.

    Codifique nomes e valores conforme `url.QueryEscape` do Go, incluindo espaços como `+`, e una os pares com `&`.

    Por exemplo, `z=9&b=2&a=hello world` vira `a=hello+world&b=2&z=9`. Deixe a seção da query string vazia quando não houver parâmetros.

    Se a interpretação da query string falhar, o cálculo da assinatura usa a string original. Evite query strings malformadas.
  </Step>
  <Step title="Normalizar os cabeçalhos assinados">
    Use nomes de cabeçalho em minúsculas. Remova espaços nas pontas dos valores, ordene os nomes lexicograficamente e una linhas `nome:valor` com LF (`\n`).

    Inclua `content-type`, `x-client-id`, `x-nonce` e `x-timestamp`. Inclua `x-content-hash` somente quando seu valor não estiver vazio.

    Inclua `x-ispb` e `x-account-number` sempre que enviá-los. Cabeçalhos de conta explicitamente vazios participam da assinatura, mas falham na seleção de conta.

    Exclua `x-signature`, `host`, `content-length`, `user-agent` e todos os demais cabeçalhos. Envie timestamp e nonce sem preenchimento adicional ou espaços nas pontas.
  </Step>
  <Step title="Calcular a assinatura">
    Una as sete seções abaixo com um LF (`\n`) como separador. Mantenha a seção vazia da query string e não acrescente LF ao final.

    Calcule o HMAC-SHA256 da string UTF-8 usando a SK original como chave. Codifique a assinatura em hexadecimal minúsculo e envie-a em `X-Signature`.

    Envie o mesmo corpo e os mesmos cabeçalhos que você assinou. Não formate nem serialize novamente o JSON após assinar.
  </Step>
</Steps>

```text
UPPERCASE_METHOD
REQUEST_PATH
CANONICAL_QUERY
CANONICAL_HEADERS
CONTENT_HASH
TIMESTAMP
NONCE
```

`CANONICAL_HEADERS` pode ocupar várias linhas. O hash do corpo, o timestamp e o nonce também aparecem nas três últimas seções; mantenha essa repetição.

### Exemplos de requisições assinadas

Defina `PAGSMILE_AK` e `PAGSMILE_SK` no seu servidor. `PAGSMILE_BASE_URL` usa o Sandbox por padrão.

Os exemplos chamam `POST /v3/bank_account` com uma credencial ACCOUNT, corpo `{}`, sem query string e sem cabeçalhos de conta.

Para selecionar uma conta com credencial USER, acrescente e assine os dois cabeçalhos de conta. A ferramenta abaixo aceita esse par.

Defina `PAGSMILE_TIMEOUT_SECONDS` como um inteiro positivo; os exemplos usam 30 segundos por padrão. No Python, o timeout vale para operações bloqueantes de socket; nos demais exemplos, limita a duração total da requisição.

Falhas de conexão e timeouts são exibidos na saída de erro e encerram o programa com erro, separadamente dos resultados de negócio em JSON. Os exemplos não repetem a requisição automaticamente.

```bash cURL
# Requer curl, OpenSSL e Python 3. Exporte PAGSMILE_SK; o auxiliar HMAC lê a chave do ambiente, nunca dos argumentos de linha de comando. Defina PAGSMILE_AK e PAGSMILE_SK. PAGSMILE_BASE_URL usa o Sandbox por padrão.
BASE_URL="${PAGSMILE_BASE_URL:-https://ebanking-openapi-sandbox.pagsmile.com.br}"
REQ_PATH="/v3/bank_account"
TIMEOUT_SECONDS="${PAGSMILE_TIMEOUT_SECONDS:-30}"
case "$TIMEOUT_SECONDS" in
  ''|*[!0-9]*|0*) echo 'PAGSMILE_TIMEOUT_SECONDS must be a positive integer' >&2; exit 1 ;;
esac
BODY='{}'

# Assine exatamente os bytes enviados. Use novos nonce e timestamp a cada tentativa.
TS=$(( $(date +%s) * 1000 ))
NONCE=$(openssl rand -hex 16)
HASH=$(printf '%s' "$BODY" | openssl dgst -sha256 -hex | sed 's/^.* //')
STRING_TO_SIGN=$(printf 'POST\n%s\n\ncontent-type:application/json\nx-client-id:%s\nx-content-hash:%s\nx-nonce:%s\nx-timestamp:%s\n%s\n%s\n%s' \
  "$REQ_PATH" "$PAGSMILE_AK" "$HASH" "$NONCE" "$TS" "$HASH" "$TS" "$NONCE")
SIGNATURE=$(printf '%s' "$STRING_TO_SIGN" | python3 -c 'import hashlib, hmac, os, sys; print(hmac.new(os.environ["PAGSMILE_SK"].encode("utf-8"), sys.stdin.buffer.read(), hashlib.sha256).hexdigest())')

curl -sS --connect-timeout "$TIMEOUT_SECONDS" --max-time "$TIMEOUT_SECONDS" -X POST "$BASE_URL$REQ_PATH" \
  -H "Content-Type: application/json" \
  -H "User-Agent: your-app/1.0" \
  -H "X-Client-ID: $PAGSMILE_AK" \
  -H "X-Timestamp: $TS" \
  -H "X-Nonce: $NONCE" \
  -H "X-Content-Hash: $HASH" \
  -H "X-Signature: $SIGNATURE" \
  --data-raw "$BODY"
```

```python Python
# Defina PAGSMILE_AK e PAGSMILE_SK. PAGSMILE_BASE_URL usa o Sandbox por padrão.
import hashlib, hmac, json, os, secrets, sys, time, urllib.error, urllib.request

BASE_URL = os.environ.get("PAGSMILE_BASE_URL", "https://ebanking-openapi-sandbox.pagsmile.com.br")
PATH = "/v3/bank_account"
AK, SK = os.environ["PAGSMILE_AK"], os.environ["PAGSMILE_SK"]
TIMEOUT_SECONDS = int(os.environ.get("PAGSMILE_TIMEOUT_SECONDS", "30"))
if TIMEOUT_SECONDS <= 0:
    sys.exit("PAGSMILE_TIMEOUT_SECONDS must be a positive integer")

payload = {}
body = json.dumps(payload, separators=(",", ":"), ensure_ascii=False).encode("utf-8")

# Assine exatamente os bytes enviados. Use novos nonce e timestamp a cada tentativa.
ts, nonce = str(int(time.time() * 1000)), secrets.token_hex(16)
content_hash = hashlib.sha256(body).hexdigest()
string_to_sign = "\n".join([
    "POST", PATH, "",
    "content-type:application/json",
    f"x-client-id:{AK}",
    f"x-content-hash:{content_hash}",
    f"x-nonce:{nonce}",
    f"x-timestamp:{ts}",
    content_hash, ts, nonce,
])
signature = hmac.new(SK.encode(), string_to_sign.encode(), hashlib.sha256).hexdigest()

req = urllib.request.Request(BASE_URL + PATH, data=body, method="POST", headers={
    "Content-Type": "application/json",
    "User-Agent": "your-app/1.0",
    "X-Client-ID": AK,
    "X-Timestamp": ts,
    "X-Nonce": nonce,
    "X-Content-Hash": content_hash,
    "X-Signature": signature,
})
try:
    with urllib.request.urlopen(req, timeout=TIMEOUT_SECONDS) as resp:
        print(resp.read().decode("utf-8"))
except urllib.error.HTTPError as err:
    print(err.read().decode("utf-8"))
except (urllib.error.URLError, TimeoutError, OSError) as err:
    print(f"Transport failure: {err}", file=sys.stderr)
    sys.exit(1)
```

```go Go
// Defina PAGSMILE_AK e PAGSMILE_SK. PAGSMILE_BASE_URL usa o Sandbox por padrão.
package main

import (
	"bytes"
	"crypto/hmac"
	"crypto/rand"
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"io"
	"net/http"
	"os"
	"strconv"
	"strings"
	"time"
)

func main() {
	baseURL := os.Getenv("PAGSMILE_BASE_URL")
	if baseURL == "" {
		baseURL = "https://ebanking-openapi-sandbox.pagsmile.com.br"
	}
	path := "/v3/bank_account"
	ak, sk := os.Getenv("PAGSMILE_AK"), os.Getenv("PAGSMILE_SK")
	timeoutSeconds := 30
	if value := os.Getenv("PAGSMILE_TIMEOUT_SECONDS"); value != "" {
		var err error
		timeoutSeconds, err = strconv.Atoi(value)
		if err != nil || timeoutSeconds <= 0 {
			fmt.Fprintln(os.Stderr, "PAGSMILE_TIMEOUT_SECONDS must be a positive integer")
			os.Exit(1)
		}
	}
	client := &http.Client{Timeout: time.Duration(timeoutSeconds) * time.Second}

	body := []byte(`{}`)

	// Assine exatamente os bytes enviados. Use novos nonce e timestamp a cada tentativa.
	ts := strconv.FormatInt(time.Now().UnixMilli(), 10)
	nb := make([]byte, 16)
	rand.Read(nb)
	nonce := hex.EncodeToString(nb)
	sum := sha256.Sum256(body)
	contentHash := hex.EncodeToString(sum[:])
	stringToSign := strings.Join([]string{
		"POST", path, "",
		"content-type:application/json",
		"x-client-id:" + ak,
		"x-content-hash:" + contentHash,
		"x-nonce:" + nonce,
		"x-timestamp:" + ts,
		contentHash, ts, nonce,
	}, "\n")
	mac := hmac.New(sha256.New, []byte(sk))
	mac.Write([]byte(stringToSign))
	signature := hex.EncodeToString(mac.Sum(nil))

	req, err := http.NewRequest("POST", baseURL+path, bytes.NewReader(body))
	if err != nil {
		fmt.Fprintln(os.Stderr, "Transport failure:", err)
		os.Exit(1)
	}
	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("User-Agent", "your-app/1.0")
	req.Header.Set("X-Client-ID", ak)
	req.Header.Set("X-Timestamp", ts)
	req.Header.Set("X-Nonce", nonce)
	req.Header.Set("X-Content-Hash", contentHash)
	req.Header.Set("X-Signature", signature)
	resp, err := client.Do(req)
	if err != nil {
		fmt.Fprintln(os.Stderr, "Transport failure:", err)
		os.Exit(1)
	}
	defer resp.Body.Close()
	out, err := io.ReadAll(resp.Body)
	if err != nil {
		fmt.Fprintln(os.Stderr, "Transport failure:", err)
		os.Exit(1)
	}
	fmt.Println(string(out))
}
```

```java Java
// Java 17+. Defina PAGSMILE_AK e PAGSMILE_SK. PAGSMILE_BASE_URL usa o Sandbox por padrão.
import java.net.URI;
import java.net.http.*;
import java.nio.charset.StandardCharsets;
import java.security.*;
import java.time.Duration;
import java.util.HexFormat;
import java.util.concurrent.TimeUnit;
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;

public class PagsmileRequest {
    public static void main(String[] args) throws Exception {
        String baseUrl = System.getenv().getOrDefault("PAGSMILE_BASE_URL", "https://ebanking-openapi-sandbox.pagsmile.com.br");
        String path = "/v3/bank_account";
        String ak = System.getenv("PAGSMILE_AK"), sk = System.getenv("PAGSMILE_SK");
        int timeoutSeconds = Integer.parseInt(System.getenv().getOrDefault("PAGSMILE_TIMEOUT_SECONDS", "30"));
        if (timeoutSeconds <= 0) throw new IllegalArgumentException("PAGSMILE_TIMEOUT_SECONDS must be a positive integer");

        byte[] body = """
            {}""".getBytes(StandardCharsets.UTF_8);

        // Assine exatamente os bytes enviados. Use novos nonce e timestamp a cada tentativa.
        String ts = Long.toString(System.currentTimeMillis());
        byte[] nb = new byte[16];
        new SecureRandom().nextBytes(nb);
        String nonce = HexFormat.of().formatHex(nb);
        String contentHash = HexFormat.of().formatHex(MessageDigest.getInstance("SHA-256").digest(body));
        String stringToSign = String.join("\n",
            "POST", path, "",
            "content-type:application/json",
            "x-client-id:" + ak,
            "x-content-hash:" + contentHash,
            "x-nonce:" + nonce,
            "x-timestamp:" + ts,
            contentHash, ts, nonce);
        Mac mac = Mac.getInstance("HmacSHA256");
        mac.init(new SecretKeySpec(sk.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
        String signature = HexFormat.of().formatHex(mac.doFinal(stringToSign.getBytes(StandardCharsets.UTF_8)));

        HttpRequest request = HttpRequest.newBuilder(URI.create(baseUrl + path))
            .timeout(Duration.ofSeconds(timeoutSeconds))
            .header("Content-Type", "application/json")
            .header("User-Agent", "your-app/1.0")
            .header("X-Client-ID", ak)
            .header("X-Timestamp", ts)
            .header("X-Nonce", nonce)
            .header("X-Content-Hash", contentHash)
            .header("X-Signature", signature)
            .POST(HttpRequest.BodyPublishers.ofByteArray(body))
            .build();
        HttpClient client = HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(timeoutSeconds)).build();
        var pending = client.sendAsync(request, HttpResponse.BodyHandlers.ofString());
        try {
            HttpResponse<String> response = pending.get(timeoutSeconds, TimeUnit.SECONDS);
            System.out.println(response.body());
        } catch (Exception err) {
            pending.cancel(true);
            System.err.println("Transport failure: " + err);
            System.exit(1);
        }
    }
}
```

### Usar a ferramenta de assinatura

A ferramenta calcula assinaturas no seu navegador sem transmitir ou persistir a SK. Ela remove os espaços em branco fora das strings do JSON antes de assinar, sem alterar nenhum valor, e gera um comando cURL em sintaxe bash com esse corpo exato. Se você informou suas chaves em [Configurar acesso à API](/pt-br/api-access-setup), a ferramenta as preenche a partir da memória desta aba.

O método é fixo em `POST`. Informe um caminho ASCII sem escapes percentuais, query string ou fragmento. Caminhos não suportados são recusados antes da assinatura.

Para outros caminhos, assine no servidor conforme as [regras de caminho e query string](#montar-a-string-a-ser-assinada). Inclua os dois cabeçalhos de conta quando sua credencial exigir.

No Sandbox, **Enviar ao Sandbox** envia a requisição assinada a partir do navegador, então a API confere o IP deste computador na lista de IPs permitidos. A política CORS da API não permite `X-ISPB` nem `X-Account-Number` vindos de navegadores; para requisições com esses cabeçalhos, execute o comando cURL no seu servidor.

<Note>
  O Playground envia as requisições diretamente do seu navegador para a API, sem proxy. A API confere o IP público deste computador na lista de IPs permitidos e retorna `4004103` se ele não estiver na lista. Adicione o endereço exato detectado em [Configurar acesso à API](/pt-br/api-access-setup). Não libere todos os IPs na lista.

  A política CORS da API não permite `X-ISPB` nem `X-Account-Number` vindos de navegadores. Se você preencher esses cabeçalhos, o Playground mostra `unable to complete request`. Com a credencial do usuário em uma operação de conta, execute o comando cURL em um servidor com IP permitido.
</Note>

Use o Playground apenas para requisições sem cabeçalhos de conta: com a credencial da conta bancária, ou com a credencial do usuário em operações de contas gerenciadas ou de assinaturas de eventos.

Cole `X-Client-ID`, `X-Timestamp`, `X-Nonce` e `X-Signature` nos campos de Authorization do Playground.

Cole `X-Content-Hash` no campo de Header correspondente. Deixe `X-ISPB` e `X-Account-Number` vazios. Defina `Content-Type` como `application/json` e cole o corpo compacto no modo JSON.

Gere novos cabeçalhos a cada tentativa. A conferência de vetor de teste compara o resultado da ferramenta com o primeiro vetor fixo acima.

## Erros de autenticação

Todos os resultados de negócio em JSON, inclusive erros de autenticação, retornam HTTP 200. Leia `code` antes de `data`; HTTP 200 não comprova sucesso.

| `code` | Exemplo de mensagem | O que fazer |
| --- | --- | --- |
| `4004101` | `Authorization is required` | Envie `X-Client-ID` com a sua AK. |
| `4004102` | `Invalid {{.header}} header` | Confira `X-Timestamp`, `X-Nonce` e `X-Signature`. A mensagem não indica o cabeçalho. |
| `4004103` | `IP address has no permission: {{.ip}}` | Autorize o IP de saída ou o CIDR do servidor. |
| `4004104` | `X-Content-Hash does not match request body` | Calcule o hash dos bytes exatos enviados. |
| `4004105` | `X-Timestamp is invalid or expired` | Confira o relógio e gere um timestamp novo. |
| `4004106` | `X-Nonce is invalid or has already been used` | Gere um novo nonce para a tentativa. |
| `4004107` | `X-Signature is invalid` | Confira a SK e as sete seções da assinatura. |
| `401` | `User is invalid` | Confira a credencial e o acesso à OpenAPI do titular. |
| `4004003` | `Permission denied` | Confira o tipo de credencial e a conta selecionada. |

Somente corpos ilegíveis ou JSON inválido retornam HTTP 400 com corpo `text/plain`. Ao contatar o suporte, informe o cabeçalho de resposta `xxx-log-id`.

Envie um `User-Agent` descritivo, como `your-app/1.0`. A borda da rede pode bloquear um valor ausente ou o valor padrão de uma biblioteca, como `Python-urllib/3.12`. Ela retorna HTTP 403 com o texto `error code: 1010` antes da autenticação. O `User-Agent` não faz parte da assinatura; alterá-lo não afeta a assinatura.

Para uma requisição `POST` com JSON assinado, a API verifica a autenticação nesta ordem. A validação para na primeira falha.

<Steps>
  <Step title="Cabeçalhos obrigatórios">
    Conferir os cabeçalhos obrigatórios de assinatura.
  </Step>
  <Step title="Timestamp">
    Validar o timestamp dentro da janela de cinco minutos.
  </Step>
  <Step title="Nonce">
    Registrar o par de AK e nonce por dez minutos. O nonce é consumido mesmo quando a assinatura falha.
  </Step>
  <Step title="Assinatura e hash do corpo">
    Verificar a assinatura e o hash do corpo.
  </Step>
  <Step title="Lista de IPs permitidos">
    Conferir o IP de origem na lista de IPs permitidos.
  </Step>
  <Step title="Seleção de conta">
    Resolver a seleção da conta.
  </Step>
  <Step title="Acesso do titular à OpenAPI">
    Conferir o acesso à OpenAPI do titular para credenciais ACCOUNT e USER.
  </Step>
</Steps>

O resultado de negócio em JSON retorna HTTP 200, inclusive nas falhas de autenticação. Leia `code` para distinguir sucesso de falha.

Para o catálogo completo, veja [erros de autenticação](/pt-br/api-reference/error-catalog#erros-de-autenticação).

## Verificar callbacks

Os callbacks usam `POST`. Verifique a assinatura com a SK associada ao `X-Client-ID` recebido antes de processar o evento.

Preserve os bytes do corpo bruto. Não interprete, formate nem serialize novamente o JSON antes de calcular o hash.

### Cabeçalhos obrigatórios dos callbacks

Os callbacks incluem os seis cabeçalhos abaixo. Diferentemente das requisições à API, os callbacks exigem `X-Content-Hash`.

| Cabeçalho | Regra de verificação |
| --- | --- |
| `Content-Type` | Use o valor recebido, sem espaços nas pontas. Não o substitua. |
| `X-Client-ID` | Localize a AK e a SK associadas. |
| `X-Timestamp` | Interprete milissegundos Unix e confira a janela de validade acordada. |
| `X-Nonce` | Confira se contém 32 caracteres hexadecimais minúsculos. |
| `X-Content-Hash` | Compare com o SHA-256 do corpo bruto em hexadecimal minúsculo. |
| `X-Signature` | Compare com o HMAC-SHA256 esperado usando comparação em tempo constante. |

Defina uma janela de validade para o timestamp dos callbacks na sua integração e aplique-a no receptor. A janela da API não define essa política.

### String a ser assinada no callback

Use a mesma estrutura de sete seções, com o caminho do callback na segunda. Una as seções com LF e não acrescente LF ao final.

```text
UPPERCASE_METHOD
CALLBACK_PATH
CANONICAL_QUERY
CANONICAL_HEADERS
CONTENT_HASH
TIMESTAMP
NONCE
```

Normalize a query string conforme [Assinar requisições](#assinar-requisições). Preserve a barra final; use `/` se a URL do callback não tiver caminho.

Inclua somente `content-type`, `x-client-id`, `x-content-hash`, `x-nonce` e `x-timestamp` nos cabeçalhos normalizados.

Remova espaços nas pontas dos valores, ordene os nomes em minúsculas lexicograficamente e una linhas `nome:valor` com LF. Exclua `x-signature` e os cabeçalhos de seleção de conta.

Calcule o HMAC-SHA256 com a SK associada. O resultado esperado contém 64 caracteres hexadecimais minúsculos.

Mantenha o hash do corpo, o timestamp e o nonce tanto na seção de cabeçalhos quanto nas três últimas seções.

### Codificação do caminho do callback

Use o caminho sem domínio, query string ou fragmento. O tipo de entrega determina se os escapes percentuais permanecem no caminho usado na assinatura.

| Tipo de callback | Caminho usado na assinatura |
| --- | --- |
| Callbacks de transações ACCOUNT | Caminho após a decodificação de URL |
| Callbacks de transações USER | Caminho com escapes de URL preservados |
| Callbacks de KYB e MED | Caminho com escapes de URL preservados |

Para `/hooks/%41`, o caminho decodificado é `/hooks/A`; o caminho com escapes continua `/hooks/%41`. Não decodifique a forma com escapes antes de assinar.

Use um caminho de callback ASCII sem escapes percentuais, como `/pagsmile/webhooks`, para que as duas formas sejam iguais.

### Proteção contra replay e confirmação de recebimento

<Steps>
  <Step title="Validar a entrega">
    Confira os cabeçalhos obrigatórios e o timestamp. Calcule o hash do corpo, monte a string a ser assinada e compare as assinaturas em tempo constante.

    Recuse entregas inválidas antes de interpretar os dados da operação.
  </Step>
  <Step title="Impedir replay e salvar o evento">
    Depois de validar a assinatura, confira e registre o par de AK e nonce de forma atômica. Associe essa proteção ao armazenamento durável do evento.

    Faça a deduplicação pelos identificadores definidos para o tipo de callback. Um nonce novo não comprova que o evento de negócio é novo.
  </Step>
  <Step title="Confirmar o recebimento">
    Retorne HTTP 200 depois de armazenar ou enfileirar com segurança o evento verificado. Processe o evento de forma assíncrona.

    A confirmação indica recebimento, não conclusão do processamento de negócio. Não execute a mesma ação duas vezes para um evento duplicado.
  </Step>
</Steps>

Trate os eventos sem depender da ordem de chegada. Siga os identificadores e as regras em [callbacks de transações](/pt-br/api-reference/webhooks/transaction-callbacks).

Respostas diferentes de HTTP 200 e falhas de transporte podem provocar novas tentativas de entrega. Veja [webhooks](/pt-br/api-reference/webhooks/overview) para entender o comportamento.

### Conferir um callback recebido

O verificador calcula no seu navegador sem transmitir ou persistir a SK. Cole os seis cabeçalhos, o corpo bruto, a query string e o caminho correto da assinatura.

Esta ferramenta aceita apenas URLs de callback com caminho ASCII sem escapes percentuais, como `/pagsmile/webhooks`. Cole o caminho recebido sem alterações; caminhos não suportados são recusados antes do cálculo da assinatura.

Para URLs com escapes, verifique no servidor conforme a [regra de codificação do caminho](#codificação-do-caminho-do-callback) do tipo de callback. Não decodifique a URL apenas para usar a ferramenta.

Ela confere o hash do corpo, a assinatura, o formato da assinatura e o formato do nonce, além de mostrar a idade do timestamp. Assinaturas com letras maiúsculas falham na verificação de 64 caracteres hexadecimais minúsculos.

Ela não aplica a janela de validade nem registra nonces.

Use um verificador no servidor com proteção contra replay no seu receptor. A ferramenta do navegador serve para diagnóstico.
